# Hack The Nest 2026 — 2 人队比赛流程

## 总体策略
1. **主赛道选 1 个，再叠加 2–3 个容易拿的 MLH 赞助商奖项。** 推荐主赛道：*Future of Intelligence* 或 *Mind and Machine*（AI 类，我们最擅长）。可以叠加的奖项：
   - **Gemini API**：用它做 AI 功能，几乎不增加工作量
   - **MongoDB Atlas**：数据库直接用它
   - **GoDaddy 域名**：领免费码注册一个好记的域名，10 分钟就能搞定
   - **DEV Writing**：赛后写一篇文章，$100
2. **只有 2 个人，所以范围要小，要做出完成度高的作品。** 一个核心功能，从头到尾都能跑通，比 5 个半成品强。评委看的是 **3 分钟 demo**。
3. **AI 编程工具全程用**（Claude Code / Cursor）。如果用 Cursor，再顺手接一个 Grok Bot，就能参加 SpaceXSI 的抽奖。

## 分工
| | 成员 A：后端 / AI | 成员 B：前端 / 产品 / 路演 |
|---|---|---|
| 主要负责 | API、Gemini 调用、数据库、部署 | UI、用户流程、PPT、demo 视频、提交文案 |
| 次要负责 | 写 README 的技术部分 | 和 mentor、赞助商沟通，确认评审标准 |

两个人每 3–4 小时同步一次（每次 5 分钟）：做完了什么、卡在哪、下一步做什么。

## 时间线（按 24 小时开发计）

### 阶段 0：开幕前 / 开幕式（约 1 小时）
- [ ] 签到，抢一个靠插座的位置
- [ ] **问清楚并记下来**：提交平台和截止时间、评审标准、各赛道的评委、demo 的形式（摆展位还是上台）
- [ ] 去赞助商的桌子转一圈，领 GoDaddy / SpaceXSI 的兑换码

### 阶段 1：想点子 + 定方案（第 0–2 小时）
- [ ] 每人提 3 个点子，按「评委爱看吗 / 24 小时能做完吗 / 能叠几个奖项」打分，选一个
- [ ] 写出一句话的产品定义：「给 **谁**，解决 **什么痛点**，靠 **什么 AI 能力**」
- [ ] 定好 MVP 的功能清单（最多 3 个功能）和技术栈
- [ ] 建好 GitHub 仓库、项目骨架，跑通一个 hello world 并部署上线（**部署要尽早做**）

### 阶段 2：核心开发（第 2–12 小时）
- [ ] A：后端 API + Gemini 调用 + MongoDB Atlas
- [ ] B：页面骨架 + 主流程 UI，先用假数据
- [ ] **第 8 小时左右做中期检查**：主流程能不能从头点到尾？不能的话立刻砍功能
- [ ] 注册 GoDaddy 域名

### 阶段 3：联调 + 睡觉（第 12–18 小时）
- [ ] 前后端联调，让主流程在线上能跑
- [ ] **两个人轮流睡 2–3 小时**（不要同时睡，也不要都不睡）
- [ ] 找 mentor 看一眼作品，收集反馈

### 阶段 4：打磨 + 冻结功能（第 18–21 小时）
- [ ] **第 18 小时冻结功能**，之后只修 bug、改 UI
- [ ] 准备 demo 用的数据，把整个流程录一遍当备用视频（防止现场断网）
- [ ] B 做 PPT（5 页：问题 → 方案 → demo → 技术 → 下一步）

### 阶段 5：提交（第 21–23 小时，**至少提前 1 小时交**）
- [ ] 提交页面写清楚：项目描述、用了哪些赞助商技术、勾选所有要参加的赛道
- [ ] 准备好 GitHub 链接（README 要干净）、demo 视频、线上链接、截图
- [ ] 如果参加 SpaceXSI，描述里要写明用了 Cursor + Grok Bot

### 阶段 6：路演（最后几小时）
- [ ] 3 分钟讲稿：先讲 30 秒痛点，然后 2 分钟 live demo，最后 30 秒讲技术亮点和赛道契合度
- [ ] 两个人都上去讲：B 讲故事，A 回答技术问题
- [ ] 针对每个要参加的赛道，准备一句「我们为什么符合这个奖项」

### 赛后
- [ ] 在 dev.to/mlh-hackathon 写一篇文章（DEV Writing Challenge，$100）
- [ ] 更新 GitHub README、LinkedIn，把项目写进简历

## 文件夹结构（整个文件夹就是一个 Git 仓库，存在 SSD 上，同步到 GitHub）
```
HackTheNest-2026/
├── CLAUDE.md             ← 给 AI 编程助手看的项目说明
├── README.md             ← 也作为 Devpost 项目描述的底稿
├── .env.example          ← 复制成 .env 后填 key（.env 不进 git）
├── docs/
│   ├── 00_比赛信息.md
│   ├── 01_比赛流程规划.md
│   ├── 02_团队协作工作流.md
│   ├── API.md            ← 前后端接口约定
│   └── TASKS.md          ← 任务板
├── backend/              ← A 负责
├── frontend/             ← B 负责
├── pitch/                ← PPT、讲稿（大视频文件不进 git）
└── assets/
```

> ⚠️ App 显示 Devpost **草稿截止周日 10 AM，最终提交截止周日 12 PM**，上面的时间线都以周日中午结束来倒推。
